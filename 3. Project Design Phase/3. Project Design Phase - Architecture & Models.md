# Phase 3: Project Design Phase
**Project:** Auto Ticket Classification using Flow Designer  

---

## 1. Phase Overview
The Project Design Phase articulates the detailed structural, logical, and database design. It validates the problem-solution fit, defines the formal proposed solution, and provides complete architectural diagrams and data schemas.

## 2. Subfolders and Deliverables
- **`Problem - Solution Fit Template/`**
  - `Problem - Solution Fit Template v1.docx`: Deep-dive validation that Flow Designer resolves the exact behavioral bottlenecks of academic callers and agents.
- **`Proposed Solution/`**
  - `Proposed Solution Template.docx`: Parameterized specification table covering problem, solution, novelty, social impact, business model, and scalability.
- **`Solution Architecture/`**
  - `Solution Architecture.docx`: Comprehensive architectural design document covering multi-tier architecture, database schema, flow logic, and security.

## 3. Architectural Highlights
```
[Academic Caller: Student/Teacher]
       |
       | 1. Submits Caller + Short Description
       v
[ServiceNow UI / Form Designer]
       |
       | 2. Inserts Record (Auto Number: INC005xx)
       v
[Custom Table: u_incident_workflow]
       |
       | 3. Triggers Asynchronous Event (Category is Empty)
       v
[Flow Designer: "Auto Classify School IT Tickets"]
       |
       +---> Condition 1: Short Description contains "Wi-Fi" / "Network"
       |     └──> Action: Update Record (Category: Network, Subcategory: Wi-Fi)
       |
       +---> Condition 2: Short Description contains "Projector"
       |     └──> Action: Update Record (Category: Hardware, Subcategory: Projector)
       |
       +---> Condition 3: Short Description contains "Forgot password"
       |     └──> Action: Update Record (Category: Access, Subcategory: Forgot Password)
       |
       +---> Condition 4: Short Description contains "Slow computer"
       |     └──> Action: Update Record (Category: Performance, Subcategory: Slow Compter)
       |
       └───> Action: Send Email
             └──> Recipient: Trigger -> Incident Record -> Caller -> Email
             └──> Subject: "Your Request for the issue has been submitted."
```
